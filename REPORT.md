# Звіт до лабораторної роботи № 6

## 1. Тема, номер і варіант

- Тема: обробка даних засобами Python (CSV, типізація, списки/словники/множини, pytest, ruff, wheel).
- Предметна область: варіант 17 — «Спортивна ліга» (той самий домен, що й у Java-блоці лаб. 1-5).
- Операційна система: Linux (Debian 13), Python 3.11+ (перевірено на 3.13.5).

## 2. Мета роботи

Створити невеликий Python-пакет, який читає CSV-файл результатів матчів,
перетворює текстові поля на типізовані значення, обчислює показники за
списками, словниками й множинами та записує детермінований текстовий звіт.
Поведінка перевіряється тестами pytest, якість коду — ruff, пакет
збирається у wheel і перевіряється в GitHub Actions на трьох ОС.

## 3. Формат CSV

Заголовок: `home,away,date,home_score,away_score,round`. Типи полів:
`home`/`away`/`date` — `str`, `home_score`/`away_score`/`round` — `int`
(перетворюються з тексту під час завантаження). Приклад екранованого рядка
(кома в назві команди):

```
"Карпати, Львів",Верес,2026-03-02,1,1,1
```

Порожній CSV (лише заголовок або зовсім порожній файл) — допустимий
випадок: `load_records` повертає порожній список, а не помилку.

## 4. Структура модулів

```
src/kzp_lab06/
├── __init__.py      -- публічний мінімальний API
├── errors.py         -- DataError
├── loader.py          -- читання CSV (csv.DictReader) і перетворення типів
├── analysis.py         -- відбір, словник, множина, build_summary
├── reporting.py         -- формування й запис текстового звіту
└── cli.py                -- аргументи командного рядка й межа помилок
```

`loader.py` не друкує звіт, `analysis.py` не відкриває файли, `reporting.py`
не читає CSV — кожен модуль тестується без підготовки файлової системи для
операцій, які йому не належать. Код запуску міститься лише в
`if __name__ == "__main__":` у `cli.py`, тому імпорт пакета нічого не
виконує й нічого не друкує.

## 5. Перетворення даних

`loader.parse_record` перетворює три текстові поля на `int`
(`home_score`, `away_score`, `round`) і нормалізує (`.strip()`) текстові
поля `home`/`away`/`date`. Приклади списків/словників/множин і
comprehensions — у `analysis.py`:

```python
def unique_teams(records: list[dict[str, object]]) -> set[str]:
    return {str(record["home"]) for record in records} | {str(record["away"]) for record in records}
```

(`matches_in_round` — list comprehension; `count_by_round` — dict
comprehension з відсортованими ключами; `unique_teams` — два set
comprehensions, об'єднані оператором `|`.)

## 6. Функції з типовим значенням, *args і **kwargs

```python
def build_summary(
    records: list[dict[str, object]],
    *metrics: str,
    min_round: int = 1,
    **labels: str,
) -> dict[str, object]:
```

`metrics` — кортеж назв метрик (`"total_goals"`, `"max_difference"`),
`min_round: int = 1` — типове значення (не змінюваний об'єкт, не створює
стану між викликами), `labels` — словник перейменувань ключів результату
(наприклад, `total_goals="Голів"`). Приклад виклику:

```python
build_summary(records, "total_goals", "max_difference", min_round=3,
               total_goals="Голів", max_difference="Макс. різниця")
```

Невідома назва метрики відхиляється явною `ValueError`, а якщо після
фільтрування за `min_round` не лишилось жодного запису — кожна метрика
отримує `0.0` (порожній результат відрізняється від помилки).

## 7. Алгоритм аналізу

- **Відбір** (`matches_in_round`) — точний збіг номера туру.
- **Агрегування за ключем** (`count_by_round`) — кількість матчів на кожен
  тур, ключі відсортовані за зростанням, щоб текст звіту не залежав від
  порядку рядків у файлі.
- **Унікальні значення** (`unique_teams`) — множина всіх команд
  (господарів і гостей разом).
- **Підсумкові метрики** (`build_summary`) — загальна кількість голів і
  найбільша різниця рахунку, рахуються від порогового туру `MIN_ROUND = 3`
  (константа варіанта, зафіксована в `reporting.py` та тут).

## 8. Обробка помилок

`DataError(ValueError)` — єдиний власний виняток. Кожна помилка містить
номер рядка (рахується від першого рядка даних, без заголовка) і причину:

| Причина | Повідомлення |
|---|---|
| бракує обов'язкового стовпця в заголовку | `У заголовку CSV бракує полів: ...` |
| порожня назва команди | `Рядок N: порожня назва команди` |
| порожня дата | `Рядок N: порожня дата` |
| нечислове чи відсутнє числове поле | `Рядок N: числове поле має помилковий формат` (`raise ... from error` зберігає першопричину `ValueError`/`TypeError`/`KeyError`) |
| від'ємний рахунок | `Рядок N: рахунок не може бути від'ємним` |
| тур менше 1 | `Рядок N: тур має бути не менше 1` |

CLI (`cli.py`) перехоплює `DataError` і повертає код завершення `1` з
повідомленням у `stderr` (без traceback); `OSError` (відсутній файл тощо)
теж код `1`; неправильна кількість аргументів — код `2`. Голий `except` не
застосовується ніде в пакеті.

## 9. Файловий звіт

## 15. Відповіді на контрольні питання

1. `pyproject.toml` описує назву пакета, мінімальну версію Python,
  dev-залежності, команду CLI (`[project.scripts]`) і налаштування ruff —
  єдине джерело конфігурації для локальної перевірки й CI.
2. Віртуальне середовище ізолює залежності проєкту від системного Python і
  від інших проєктів, щоб версії пакетів не конфліктували.
3. `newline=""` передає керування роздільниками рядків самому модулю
  `csv`, а не менеджеру відкриття файла — інакше `csv` міг би неправильно
  обробити перенесення рядка всередині лапок.
4. `csv.DictReader` без додаткового перетворення повертає лише рядкові
  значення (`str`) для кожного поля — навіть числові стовпці потрібно
  явно перетворювати (`int`/`float`).
5. `split(",")` ламає поля, що містять кому в лапках (наприклад, `"Карпати,
  Львів"` розпалось б на два поля) — загальний CSV-парсер мусить
  відрізняти кому-дані від коми-роздільника.
6. Список зберігає порядок і допускає повтори; словник зіставляє унікальний
  ключ зі значенням; множина зберігає лише унікальні значення без
  гарантованого порядку.
7. Comprehension зручний для одного прозорого перетворення чи відбору;
  якщо з'являються кілька вкладених умов або складне накопичення, звичайний
  цикл зазвичай читабельніший.
8. Усередині функції `*args` — це кортеж (`tuple`) позиційних аргументів
  понад перелічені параметри, а `**kwargs` — словник (`dict`) іменованих
  аргументів понад перелічені.
9. Змінний об'єкт (наприклад, список) як значення за замовчуванням
  небезпечний, бо Python створює його один раз при визначенні функції, а
  не при кожному виклику — зміни в одному виклику лишаються в наступних.
10. `raise DataError(...) from error` зберігає першопричину (`error`) в
   атрибуті `__cause__` нового винятку — трасування показує обидва
   винятки, а не лише останній.
11. Завантаження, аналіз і запис звіту розділені на модулі, щоб кожен
   можна було тестувати незалежно (без підготовки файлової системи для
   `analysis.py`) і змінювати, не чіпаючи інші відповідальності.
12. `with` гарантує закриття файла навіть якщо під час запису виникне
   виняток — ресурс не лишається відкритим у разі помилки.
13. Детермінований порядок (сортування ключів словника перед виводом)
   робить текст звіту незалежним від порядку рядків у вхідному файлі й від
   внутрішнього порядку вставлення в словник.
14. Для порожнього CSV перевіряють: файл лише з заголовком і зовсім
   порожній файл — обидва повертають порожній список записів, а не
   помилку.
15. Тест поведінки перевіряє зовнішній результат виклику публічної функції
   (вхід → вихід), а не назви чи значення внутрішніх змінних реалізації.
16. `pytest` знаходить файли `test_*.py`/`*_test.py` і в них функції
   `test_*`.
17. `ruff check` перевіряє стиль і типові помилки коду; `ruff format
   --check` перевіряє форматування, не змінюючи файли.
18. CLI повертає `0` після успіху, ненульовий код (`1` — помилка даних чи
   файлової системи, `2` — неправильні аргументи) для очікуваної помилки.
19. У CI запускаються і тести, і аналізатор, і пакетування, бо кожен
   перевіряє інше: тести — поведінку, `ruff` — якість і стиль коду, збірка
   wheel — що пакет взагалі можна встановити й запустити окремо від
   робочого дерева розробника.
20. У REPORT декларуються: формат CSV і приклад екранованого рядка,
   структура модулів, приклади comprehensions і типової функції, повний
   текст очікуваного звіту, таблиця помилок, результати тестів/ruff/wheel
   і посилання на CI.
